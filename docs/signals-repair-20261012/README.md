# 选股结果显示与后台更新故障修复

日期：2026-10-12。修改位于本地分支 `fix/signals-snapshots`。本次开始实施工作包 B，并补齐与故障直接相关的 C 阶段门禁及恢复机制。所有最终验证由 **gpt-6-luna（6luna）** 执行；最终记录见 [6luna 验证报告](luna-validation.md)。

## 修复行为

- `artifacts/results.db` 保存不可变结果和版本。新结果先暂存并校验，再事务切换发布指针；失败不会删除旧结果或旧元数据。
- `GET /api/signals/snapshot` 在一次读取中返回列表、统计、日期、版本、任务、核验与操作权限。新页面不再拼接两个接口，不从请求路径触发全历史审计或训练。
- 后台审计、采集、模型计算或连接异常时保留旧排名，并显示数据截止/生成时间、阶段和失败原因。核验未知、版本改变、过期或更新正在运行时，操作暂停。
- 核验、结果状态和权限独立描述。合法空结果与首次无结果、页面筛选无匹配、撤销分别显示；真实筛选漏斗随版本保存。
- 撤销记录持久化，不随缓存或重新核验恢复。被撤销的输入版本不能通过新 UUID 或新生成时间重新发布。
- 模拟推演和指令读取同一已发布版本。自动执行及绑定结果的买入检查当前版本、有效期、行情指纹与风险；结果库启用后，手动买入也必须提供 `snapshot_id`。独立卖出保持可用。
- 发布/撤销与短操作事务使用结果库写锁串行，避免核验后、买入提交前的版本撤销竞争。
- 后台任务持久化阶段、起止时间、错误和进程身份。进程级租约防止浏览器重试、多进程与直接命令行重复生成；恢复仅把已经死亡的 owner 任务标为中断。
- 新服务启动时，将有完整来源/时间元数据的旧 CSV 导入为历史版本；不把未知参数和模型身份的旧文件直接升级为当前有效。重新计算服务结果时，保留原预测账本的冻结记录。

## 接口迁移

旧 `/api/signals`、`/api/signals/stats` 保留兼容，但新页面只使用 `/api/signals/snapshot`。运行中的旧 Python 进程需要加载新后端，才拥有该路由；仅刷新浏览器不能替代 API 重启。

例：

```sh
curl http://127.0.0.1:8888/api/signals/snapshot
```

手动模拟买入请求：

```json
{
  "snapshot_id": "从当前 snapshot 响应取得的版本",
  "code": "000001",
  "side": "BUY",
  "shares": 100,
  "price": 10
}
```

过时、撤销、缺少版本引用或状态无法确认的绑定操作返回409。结果库不可读时，快照查询返回503；页面保留已有带日期内容，标为历史回看并暂停操作。
